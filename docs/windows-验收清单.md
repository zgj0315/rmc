# Windows 人工验收清单

这份清单是**整条流水线里所有「开发机上验不了」的东西的唯一出口**。

开发在 macOS 上做，CI 在 ubuntu 与 windows runner 上跑。两者合起来仍然够不着
下面这些：真实的 Win32 调用结果（托盘、DPAPI、SSPI、电源与网络事件）、真实的
显示缩放、真实的字体、真实的企业网络、以及 `main()` 从进程启动到窗口出现这
一整段。**每一条都标了出处**，方括号里是设计评审的编号或报告位置，想知道
「为什么要验这一条、验不过是什么后果」就去翻那一条。

## 怎么用

- 每次发版**从头走一遍**，不要只走改动相关的部分——这些项之间互相影响
  （例：改了窗口尺寸会同时影响 §2 与 §3）。
- 每一项记录：机型、Windows 版本与内部版本号、显示缩放比例、结果
  （通过 / 失败 / 不适用）。失败的记现象，不要只记「不通过」。
- 带 ★ 的是**阻断发布**项：不通过就不发。
- 至少要有两套环境：一台 1080p @150% 缩放的普通笔记本，一台域内机器
  （§8 的代理与 SSPI 只有域内才验得到）。

## 0. 发布前：签名

签名**刻意不在 CI 里做**，代码签名证书不进仓库 [W222]。流程是：

1. 从 GitHub Actions 的 `app` 工作流下载 `rmc-portable` 产物，解出 `rmc.exe`。
2. 在持有代码签名证书的那台机器上：

   ```
   signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a rmc.exe
   signtool verify /pa /v rmc.exe
   ```

3. ★ `signtool verify` 必须报成功，且输出里有时间戳（`/tr` 那一项）。没有
   时间戳的话，证书一过期，已经发出去的所有副本会同时开始报「发行者未知」。
4. ★ 下面**所有**条目都要在**签过名的那一份** exe 上走，不是 CI 直接下载的
   那一份——签名会改变文件，SmartScreen 的反应也只有签过才看得到。

## 1. 启动与权限

- [ ] ★ 双击 `rmc.exe` 直接启动，**没有 UAC 提权提示**
      [方案 §3.9；`crates/rmc-app/rmc.manifest` 的 `asInvoker`]。
- [ ] 右键 `rmc.exe` → 属性 → 数字签名：显示的是公司的证书，时间戳有效。
- [ ] 在一台**从没跑过**这个程序的机器上首次运行：SmartScreen 的提示是
      「已验证的发布者」而不是「未知发布者」。
- [ ] ★ 首次启动到窗口出现的整个过程不报错、不闪退
      [W216：`main()` 的装配与启动**至今零自动化证据**——
      `rmc_app::assemble(core).run()` 换成一句空操作，本地四道语义闸门
      全绿。这一条是它唯一的实检]。
- [ ] ★ 启动后控制台窗口**不出现**（`windows_subsystem = "windows"`）。
- [ ] ★ 第一次真跑时盯一眼有没有 `Cannot start a runtime from within a runtime`
      [W113：`main()` 里我们自己建了一个 tokio 运行时给内核用，iced 的
      `tokio` feature 又会建它自己的一个。`runtime.enter()` 的守卫**只罩住
      `spawn_core` 那一行**，靠的就是这个边界；守卫的作用域一旦被人放大到
      `run()` 上，就是这条报错。macOS 上跑不出这个组合]。
- [ ] 重复启动第二个实例：已有窗口被置前，不出现两个窗口
      [Task 1 的 `SingleInstance`；互斥体名那一段是 `#[cfg(windows)]`，
      macOS 上连编译都不编译]。
- [ ] 在 RDP 会话中启动成功。
- [ ] 在没有独立显卡驱动的虚拟机中启动成功
      [iced 只开 tiny-skia、没有 wgpu，理论上没有 GPU 初始化这条会失败的路，
      这一条是在确认这个理论]。

- [ ] ★ **固定 520×720 在 1080p @150% 缩放下放得下**

## 3. 托盘 [Task 11 报告 §6、task-11-fix-1-report.md §5]

托盘那 114 行 `unsafe` **在真 Windows 上一次都没跑过**，下面每一条都是冲着
一处具体的没把握去的。

- [ ] ★ 起客户端 → 通知区出现一个**灰色**圆点，悬停提示是
      「远程运维客户端 — 未开启 / 远程维护默认关闭，由现场人员确认后开启」
      [`CreateIcon` 用 32bpp DDB 传 RGBA。MSDN 的例子是 1bpp/4bpp，32bpp 是
      「能用但少见」的路子，个别 Windows 版本可能忽略 alpha。最坏结果应当是
      **硬边圆点**（我们同时给了 AND 掩码），不该是空白或黑块]。
- [ ] 点「开启远程维护」→ 圆点依次变**蓝**（预检/连接中）→ **绿**（已连接），
      悬停提示跟着变。
- [ ] ★ **换状态时圆点不闪空白** [W201：`NIM_MODIFY` 与 `DestroyIcon` 的先后。
      连上→断开→再连上，**反复切五次以上**，盯住通知区：颜色应当直接从一种
      变成另一种，中间不出现空白或默认图标；也要留意通知区里**别的**图标有没有
      异常（句柄复用时旧顺序可能让 Explorer 画出别的对象）。
      这条**零自动化证据**——改回旧顺序，本地四道语义闸门全绿]。
- [ ] ★ **杀掉 explorer.exe 再让它起来，托盘图标还在吗**
      [W205。任务管理器结束 `explorer.exe`，等它自动重启（或手动新建任务
      `explorer.exe`）。**预期结果是图标会永久消失**——我们的托盘宿主是一个
      `HWND_MESSAGE` 消息专用窗口，收不到 Explorer 重启时广播的
      `TaskbarCreated` 消息，所以不会重新注册。此后每次状态变化的
      `NIM_MODIFY` 只会静默失败。**如果真的消失了，这一条记「已确认缺陷」
      而不是「失败」**，处置见 `docs/交付前还剩什么.md` 第 2 条]。
- [ ] 让远程工程师连入 → 弹气泡「远程维护 / 1 个远程会话已接入一体机」；
      断开 → 弹「1 个远程会话已结束」。
- [ ] **上一个工程师断开、下一个同一拍接进来**：两条通知都要弹
      [`SessionDelta::between` 按会话 id 比而不是比个数，就是为了这一拍]。
- [ ] 停掉一体机 sshd → 圆点变**橙**，弹「一体机不可达 / 隧道正常，但连不上
      一体机，请检查设备与网段」；恢复 sshd → 弹「一体机已恢复」。
- [ ] 拔网线 → 圆点变**琥珀**，**不弹任何通知**。
- [ ] ★ 关掉客户端 → 圆点**当场消失**，不留幽灵图标（鼠标划过才消失也算失败）
      [`Drop` 里 `NIM_DELETE` 与 iced 窗口销毁的先后]。
- [ ] 制造一条很长的失败文案（例如改 hosts 让 TLS 证书名不符）→ 悬停提示
      应当被截断并以 `…` 结尾，不是乱码、不是空白。
- [ ] 圆点颜色与维护页状态卡上的圆点颜色**始终一致**
      [W194：托盘取色直接用 `model.status_card().dot`，不另写一张表；这一条
      是在确认那条共享真的到位]。
- [ ] 点托盘图标**没有任何反应**（没有菜单、不显示/隐藏窗口）——这是**已知的
      刻意不做**，不是缺陷 [Task 11 报告 §8 第 1 条]。
- [ ] 托盘图标是一个纯色圆点、不是产品图标——同样是**已知的刻意不做**
      [Task 11 报告 §8 第 2 条]。
- [ ] 客户端跑着时用 Process Explorer 看线程：应当有一个每 2 秒醒一次的线程；
      退出客户端后它随进程消失 [W198]。

## 5. 连接流程

- [ ] 预检四项逐项变绿，状态卡为蓝色。
- [ ] 连接成功后凭据区隐藏，地址锁定，状态卡变绿。
- [ ] 已连接时长每秒递增，旁边没有「剩余」字样。
- [ ] 远程工程师连入后，列表出现一条会话并显示双向流量。
- [ ] 点某条会话的「断开」，只有那一条断开，隧道与其他会话不受影响。
- [ ] 点「停止远程维护」后回到未开启，运维服务器上的端口立即释放。
- [ ] ★ 全程界面不卡顿——尤其是每秒一次的时长刷新
      [发布配置用的是 `opt-level = "z"`，而渲染是纯软件光栅化（tiny-skia，
      没有 wgpu）。判断是「这个窗口只有文字和几个按钮，看不出差别」，这一条
      是在验那个判断。真有迟滞，第一件该试的事是把根 `Cargo.toml` 的
      `opt-level` 改成 `3`]。

## 6. 异常路径

- [ ] 密码填错：回到未开启，密码框清空，其余已填内容保留，**不自动重试**。
- [ ] 停掉一体机 sshd：状态卡变橙，文案为一体机不可达，隧道保持。
- [ ] 恢复一体机 sshd：橙色自动回到绿色。
- [ ] 拔网线：状态卡变黄显示第 n 次重连，不弹通知。
- [ ] ★ 插回网线：**立即**重连而不是等满退避
      [Task 5 的网络事件监听器是 `#[cfg(windows)]` 的 NLM 轮询，macOS 上
      整块不编译]。
- [ ] ★ 合盖休眠再唤醒：几秒内恢复已连接，日志里有休眠恢复记录
      [同上，电源事件监听器]。
- [ ] 改掉运维服务器的 host key 后重连：状态卡变红，文案指出 host key
      不一致，**不重试**。
- [ ] 任务管理器强杀进程：运维服务器上约 30 秒内回收端口，无残留连接。
- [ ] **制造一次 panic**（没有现成入口的话，跳过这一条并记「无法验证」）：
      预期是**哪儿都找不到它为什么崩**——主线程 panic 则进程退出，隧道任务
      panic 则界面还活着、隧道没了
      [`panic = "abort"` 已在 `b8685f6` 去掉，三层栈展开兜底都还在；但
      `strip = true`，而 GUI 子系统没有控制台——panic 那行字写进一个没人接的
      stderr。这是**已知的缺口**，见 `docs/交付前还剩什么.md` 第 1 条]。

## 7. 企业网络（需要域内环境）

- [ ] 系统代理为静态代理：出网一行显示该代理，连接成功。
- [ ] 系统代理为 PAC：出网一行显示 PAC 求值出的代理，连接成功
      [Task 2 的 WinHTTP 调用，`#[cfg(windows)]`]。
- [ ] ★ 代理要求 Negotiate 认证：**无需输入任何代理凭据**即连接成功，
      诊断页「代理认证（SSPI Negotiate）」为通过
      [Task 3 的 `NegotiateContext`。SPN 必须用**代理主机名**而不是认证方案
      ——接错了在开发机上一个字都看不出来]。
- [ ] 代理只支持 Basic 认证：诊断页明确显示「代理要求认证且协商失败」，
      而不是连接超时。
- [ ] 客户网络有 TLS 审计设备：诊断页显示证书链不受信任，并给出放行名单的
      处置建议。

## 8. 凭据与「记住密码」[W21 / W200 / W202]

- [ ] 不勾「记住密码」：重开客户端后密码框为空。
- [ ] 勾「记住密码」、连接成功 → 关掉再打开：账号、运维服务器地址、口令
      都回来了，勾是勾上的，密码框下面一行小字是
      「已从本机取回记住的密码（能不能登录运维服务器要等这次连接的结果）」。
- [ ] ★ **换一个 Windows 账号登录同一台机器**（或把 `%LOCALAPPDATA%\rmc`
      整个拷到另一台机器）→ 密码框**为空**、**不报错**，并且密码框旁出现
      「记住的密码解不开：密文绑定保存它的那个 Windows 账号，换了账号或换了
      机器就解不开。请重新输入密码并再次勾选记住密码」
      [W21。**这是真 DPAPI 唯一验得了的一格**——`DpapiSealer` 在开发机上
      一次都没执行过。三件事要同时成立：不崩、不报错、那句话真的出现]。
- [ ] 取消勾选「记住密码」→ `%LOCALAPPDATA%\rmc\secrets\` 下那个 `.sealed`
      文件与 `last-account.txt` **当场**消失（不等下一次连接）。
- [ ] 账号 A 记住 → 退出 → 打开把账号改成 B → 取消勾选 →
      `secrets\` 下**一个 `.sealed` 都不剩** [W202]。
- [ ] 账号 A 记住 → 改成 B 连成功（仍勾着）→ `secrets\` 下**只有一个**
      `.sealed`，下次启动取回的是 B [W202 另一半]。
- [ ] 勾着「记住密码」连续连三次，每次退出重进密码框都是填好的 [F5]。
- [ ] 用记事本打开 `%LOCALAPPDATA%\rmc\last-account.txt`：只有三行
      （账号、主机、端口），**没有口令**。
- [ ] ★ 在整个 `%LOCALAPPDATA%\rmc\` 下搜索刚用过的密码明文，必须**搜不到**。

## 10. 日志页

- [ ] ★ **打开日志页不崩**，时间与等级两列是**等宽对齐**的
      [W179/W190。日志页左边两列用 `monospace_family("windows")` 挑出来的
      **Consolas**。这一档 macOS 上**没有任何东西验得到**，而猜错的失败形态
      **不是「字体不好看」，是渲染管线整数溢出 panic**：族名解析不到任何字面
      时，中文那条回退路会算出一个巨大的字形 x 坐标，
      `cosmic-text/src/glyph_cache.rs:100` 的 `trunc + 1` 当场溢出。
      所以这一条要在**装了中文语言包、日志里有中文**的机器上验，
      而且要滚到底——一行都不能少看]。
- [ ] 在一台**中文版** Windows 与一台**英文版 + 中文语言包**的机器上各验一遍
      （Consolas 从 Vista 起每版都带，但语言包会影响回退链）。
- [ ] 四个标签都带计数，搜索能过滤。
- [ ] 日志正文**不是**等宽字体——**刻意的**，见上面那条崩溃
      [Task 10 报告 §7.3 第 10 条]。
- [ ] 错误等级那一列显示的是 `ERROR` 而不是画板上的 `ERR`——刻意的。
- [ ] 搜索框**没有**放大镜图标——已知不做。
- [ ] ★ 让日志总量超过 16MB（`LOG_TOTAL_BUDGET`）再导诊断包：确认包里

## 11. 长时间挂机

- [ ] 挂 8 小时以上：内存不持续增长，隧道保持，日志没有异常刷屏

- [ ] 期间合盖 / 唤醒 / 断网 / 复网各来一次，状态都能自己回到绿色。
