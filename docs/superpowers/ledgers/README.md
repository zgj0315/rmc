这三份是 Gateway、rmc-core、rmc-win 与 rmc-app 三个计划执行期间的裁决记录
（前两份 R1–R99，第三份 W1–W228）。
每条写着：决定了什么、为什么、以及**错了的代价**。

留在库里不是为了存档。结论大多已经回填进代码注释与 `docs/方案设计.md`，
但**推理过程只在这里**——而这个项目里代价最高的几次返工，都是因为
「只看到结论、不知道它为什么是这个结论」。前两份留下来的时候，后面还有
`rmc-win` 与 `rmc-app` 要做，它们果然撞上了同一批问题；第三份留下来，
是因为后面还有「再完善」那一轮与 Windows 真机验收——

## 前两份里，后续计划最该先读的

**SSPI 的 trait 形状**（rmc-core 账本，Task 5 审查段）。`ProxyAuthenticator::next_token`
收的是 `&self`，足以跨多段协商承载 SSPI 上下文，但 Windows 实现必须把
`CredHandle`/`CtxtHandle` 包进 `std::sync::Mutex`（trait 要求 `Sync`，不能用
`RefCell`），而且**每次连接尝试都要新建一个实例**（Negotiate/NTLM 是连接绑定的）。
「新一轮协商开始」的唯一信号是首次调用时 `challenge == None`。

**`start_paused` 旁边不要放真实 I/O**（R77）。tokio 虚拟时钟的自动前进量取自
时间轮的**层级槽边界**（`64^level` 毫秒），不是定时器的真实到期时刻。于是一次
真实 I/O 的 `await` 会让虚拟钟一步跳掉 262 秒，把 300 秒的预算吃掉大半——
现象是「快速假超时」而不是「挂死」。规避手法：用阻塞的
`std::net::TcpStream::connect_timeout`，完全不经 tokio 的 I/O driver。

**一正一反必须成对**。「关掉证书校验」这个回归，只有
`wrap_tls_accepts_…` 与 `wrap_tls_rejects_…` 这一对才抓得到，任何一条单独都
证明不了——前者在校验被关掉时照样绿。DPAPI 的读写、SSPI 的成功/失败都该照这个形状写。

**测试通过 ≠ 验证了它名字声称的事**。这两个计划一共抓到 **18 个**反例，
形态各不相同：断言永远不可能失败的、只查缺失不查存在的、一次变两个变量所以
对比不成立的、一条配置性质靠两个指令撑着所以删一个照样绿的、关键词撞车查错了
步骤的、在分类被故意对调之后照样通过的（因为 DNS 被劫持、错误来自别处却恰好
落进被改坏的分支）、以及最后那个——断言写对了、泄漏也真的发生了、事件也真的
被捕获到了，只是 `&[u8]` 的 `Debug` 渲染成十进制数组，所以 ASCII 子串匹配
认不出来。

对策是一条纪律，值得原样继承：**每条关键测试上方写明「改实现的哪一行会让它
变红」，并且真的去改一遍确认**。这份代码里几乎每条关键测试都有这句注释，
不少后面还跟着「本地实测过」。

**让错的东西构造不出来，而不是写注释劝阻**。`ValidatedAddresses`、`Fingerprint`、
`HostPort` 字段私有、`Error::Io` 摘掉 `#[from]`——四次都是在「还没有调用方、
改动成本为零」的时点做的。这个时机判断比手法本身更值得复用：DPAPI 的密文、
SSPI 的上下文句柄都是同一类候选。

**两个实测出来的数字，都不等于算式推的那个**。Gateway 侧反向端口回收约
**80 秒**（约 8 × `ClientAliveInterval`），客户端 keepalive 判定断线约
**40 秒**（4 × interval，russh 的 `alive_timeouts > keepalive_max` 是第 4 次
才越界）。而 `10 × 3 = 30` 两边都不成立，比例常数还不一样。
方案 §3.10 那条「必须实测、不许推算」的规范性要求，就是为这件事写的。

## 第三份里最该先读的

**`#[cfg(windows)]` 那一层，本机的闸门按构造看不见语义改动**（Task 5，八枪实测）。
两道 windows-gnu 闸门一道只 build、一道只 clippy，**都不跑测试**——连把
`Box::leak` 换成悬垂栈指针都六道全绿。对策是两条，缺一不可：平台判断写成
收 `os: &str` 的**纯函数**而不是一对 `cfg`（`monospace_family`、
`file_manager_for`、`AppPaths::from_env`、`manifest_embed::plan`），让 Windows
那一档在 macOS 上也验得到；再加一个真跑测试的 `windows-2022` job。
**即便如此，Win32 封装层本身仍然一条测试都没有**，只能靠
`docs/windows-验收清单.md`。

**「做不到」被评审推翻了三次，三把钥匙都值得留着。** W146：`iced_test` 看不见
样式，但把样式与文字解耦之后，只渲染**最小子元素**做差分快照就够得着边框颜色。
W165：它看不见样式，却看得见 `bounds`——位置与大小可以直接断言。W177：
`iced::Program::boot()` 是公开的，取得出**状态**，于是 `main()` 里最后两根线
搬进 `assemble()` 之后就有了靶子。

**`iced::Font::MONOSPACE` 在这个项目里有毒**（W179）。cosmic-text 把泛等宽族
硬编码绑在 `Noto Sans Mono` 上，而默认安装的 Windows 11 不带它；族名解析不到时
中文会让 `glyph_cache.rs:100` 溢出 panic，**而且那个 panic 会毒掉全局字体锁**，
一条测试炸、同一个二进制里别的快照测试全跟着红。运行时是同一套字体系统，
不是测试环境特有的。

**「先完成，再完善」的判据是成本会不会随时间涨，不是严重度**（W124）。
仍然当场修的：正确性 bug、需求违反、**下游消费者还是零的跨任务契约**、后面任务
要在上面加东西的测试脚手架。其余一律记账——账在 `docs/交付前还剩什么.md`。

**推理又输给了实测三次。** W113 推出「Linux 上窗口大概率起不来」，实情是
整个 crate **编不过**（W225，softbuffer 零后端）。`panic = "abort"` 的理由写着
「全仓库 `catch_unwind` 零处、已 grep 核过」，而 `events.rs` 里就有一处生产用的，
它的文档注释还在七个任务之前预言过这件事。W219 断言「`cargo deny` 根本不在
CI 里」，依据是一条 `grep … | head -3`——**截断的搜索结果不能用来证否**。

**第一次真上 CI 才看得见的两类**（W226、W228）。`Path::display()` 在 Windows 上
渲染成 `view\maintain.rs`：锚点表前三条不带分隔符所以过了，恰好死在第一条带
`/` 的上面。另一类是**把环境假设写成性质断言**——一条测试要求「本机这一档
必须有等宽字体族」，而它自己上面刚断言 Linux 那一档是 `None`；本机恒真，
十二个任务里没人见过它红。

**「测试通过 ≠ 验证了名字声称的事」又添了几种形态**：不是绿、是**永不结束**；
「改哪一行会变红」的注释本身是假的（三张空头支票，按字面注入实测全绿）；
变异注入的「确认」自己退化成 no-op（needle 带了换行，`grep -F` 把空模式
匹配到每一行）；数字取自一棵中间状态的树。

**工具纪律，每一条都来自一次真实事故。** 这台 macOS 没有 `timeout`，用
`perl -e 'alarm shift; exec @ARGV' <秒> <命令>`；**不写 `trap`，绝不 `kill 0`**
（第三次孤儿进程事故：zsh 97.9% 空转 14.5 分钟）。变异验证：注入前断言锚点
命中数恰为 1、**按整行而不是子串想**，注入后 `grep -c` 确认，needle 不许带换行；
`sed -i.bak` + `mv` 会让 mtime 回退、cargo 复用被改坏的产物，要用会推进 mtime 的
写法并在还原后 `touch`。草稿区是多个 agent 共享的，脚本放进各自的私有子目录。
每一轮结束清掉自己的 `CARGO_TARGET_DIR`——攒到过 47GB，把盘撑满、
让容器复现死在半路。
