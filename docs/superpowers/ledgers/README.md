## 几条后续计划最该先读的

**SSPI 的 trait 形状**（rmc-core 账本，Task 5 审查段）。`ProxyAuthenticator::next_token`
收的是 `&self`，足以跨多段协商承载 SSPI 上下文，但 Windows 实现必须把
`CredHandle`/`CtxtHandle` 包进 `std::sync::Mutex`（trait 要求 `Sync`，不能用
`RefCell`），而且**每次连接尝试都要新建一个实例**（Negotiate/NTLM 是连接绑定的）。
「新一轮协商开始」的唯一信号是首次调用时 `challenge == None`。

**`start_paused` 旁边不要放真实 I/O**（R77）。tokio 虚拟时钟的自动前进量取自
时间轮的**层级槽边界**（`64^level` 毫秒），不是定时器的真实到期时刻。于是一次
真实 I/O 的 `await` 会让虚拟钟一步跳掉 262 秒，把 300 秒的预算吃掉大半——
现象是「快速假超时」而不是「挂死」。规避手法：用阻塞的
`std::net::TcpStream::connect_timeout`，完全不经 tokio 的 I/O driver。

**一正一反必须成对**。「关掉证书校验」这个回归，只有
`wrap_tls_accepts_…` 与 `wrap_tls_rejects_…` 这一对才抓得到，任何一条单独都
证明不了——前者在校验被关掉时照样绿。DPAPI 的读写、SSPI 的成功/失败都该照这个形状写。

**测试通过 ≠ 验证了它名字声称的事**。这两个计划一共抓到 **18 个**反例，
形态各不相同：断言永远不可能失败的、只查缺失不查存在的、一次变两个变量所以
对比不成立的、一条配置性质靠两个指令撑着所以删一个照样绿的、关键词撞车查错了
步骤的、在分类被故意对调之后照样通过的（因为 DNS 被劫持、错误来自别处却恰好
落进被改坏的分支）、以及最后那个——断言写对了、泄漏也真的发生了、事件也真的
被捕获到了，只是 `&[u8]` 的 `Debug` 渲染成十进制数组，所以 ASCII 子串匹配
认不出来。

对策是一条纪律，值得原样继承：**每条关键测试上方写明「改实现的哪一行会让它
变红」，并且真的去改一遍确认**。这份代码里几乎每条关键测试都有这句注释，
不少后面还跟着「本地实测过」。

**让错的东西构造不出来，而不是写注释劝阻**。`ValidatedAddresses`、`Fingerprint`、
`HostPort` 字段私有、`Error::Io` 摘掉 `#[from]`——四次都是在「还没有调用方、
改动成本为零」的时点做的。这个时机判断比手法本身更值得复用：DPAPI 的密文、
SSPI 的上下文句柄都是同一类候选。

**两个实测出来的数字，都不等于算式推的那个**。Gateway 侧反向端口回收约
**80 秒**（约 8 × `ClientAliveInterval`），客户端 keepalive 判定断线约
**40 秒**（4 × interval，russh 的 `alive_timeouts > keepalive_max` 是第 4 次
才越界）。而 `10 × 3 = 30` 两边都不成立，比例常数还不一样。
方案 §3.10 那条「必须实测、不许推算」的规范性要求，就是为这件事写的。
