# 运维服务器（rmc-gateway）

一个二进制。不装软件包，不要域名，不要证书，不需要 root。

## 部署（一台干净的 x86_64 Linux）

1. 建一个普通用户（或用现有的），把 GitHub Actions `core` 工作流的
   `rmc-gateway-linux-x86_64` 产物拷到它的 PATH 里（musl 静态链接，不挑发行版）；
2. `rmc-gateway init --public-addr <这台机器的公网 IP>:22000`
   —— 这个地址会写进每一条连接码，客户端照它拨号；
3. 防火墙放行 TCP **22000–22999**（22000 给现场客户端，22001–22999 给远程工程师）；
4. `rmc-gateway serve` 先在前台跑通一次（要收窄工程师来源就带上
   `--engineer-allow <CIDR>`，可重复给）；
5. 开机自启用 `rmc-gateway service print` 生成的 systemd 单元，安装命令就印在它
   输出开头那几行注释里（本程序自己不装、不改系统）。
   **`service print` 时要把你打算让 `serve` 用的选项原样带上**：

   ```
   rmc-gateway service print --listen 0.0.0.0:22000 --engineer-allow 203.0.113.0/24
   ```

   单元里的 `ExecStart=` **只包含你这一次传进去的那些**。第 4 步前台试跑用过的参数
   **不会**被记住——漏带 `--engineer-allow`，装出来的服务就是「反向端口对所有来源
   开放」，而且**不报任何错**。一条都没带时，`service print` 会在输出的注释区印一行
   提醒；
6. 记下 `rmc-gateway fingerprint` 的输出并**备份 `~/.rmc-gateway/`**
   —— 身份密钥丢了，所有连接码作废，得重新发一遍。

**两条顺序上的硬约束**（不满足时 systemd 直接拒绝启动，不是警告）：

- **先 `init`，再装单元。** 单元里的 `ReadWritePaths=` 指向数据目录，而它指向一个
  不存在的路径时，systemd 建 mount namespace 就会失败。上面第 2 步在第 5 步之前，
  别调换。
- **`service print` 要在能解析到 `$HOME` 的环境里跑**（普通登录 shell 即可）。
  `HOME` 与 `USERPROFILE` 都没有时，数据目录会回退成相对路径 `./.rmc-gateway`，
  生成的 `ReadWritePaths=` 不是绝对路径，systemd 同样拒绝。在 `sudo -i`、cron 或
  容器里跑它，就显式传一个**绝对路径**的 `--data-dir`。

## 开通账号 / 重置口令 / 吊销 / 看谁在线

```
rmc-gateway account add <账号>     # 开通，端口自动取区间里最小的空闲号（--port 可指定）
rmc-gateway account passwd <账号>  # 重置口令，新口令只显示这一次
rmc-gateway account revoke <账号>  # 吊销，最迟 10 秒内踢掉在线会话
rmc-gateway account list           # 所有账号、端口、启用状态与各自的连接码
rmc-gateway status                 # 本机是否在跑、有哪些在线隧道
```

`account add` 打印四行：账号与端口、**连接码**、**初始口令（只显示这一次）**、
给远程工程师的 ssh 命令。连接码里没有秘密，可以走普通渠道发；**口令单独发**。
连接码随时能用 `account list` 重取，口令重取不了，只能 `account passwd` 重置。

**这几条命令都要用跑 `serve` 的那个用户运行，不要加 `sudo`。** 用 `sudo` 跑
`account add/passwd/revoke`，写出来的 `accounts.toml` 会变成 root 所有、0600，
随后普通用户身份的 `serve` 就再也读不到它。现在这几条命令自己会先检查数据目录
的属主、属主不符直接拒绝执行；真的已经跑成这样了，用
`sudo chown -R <serve 用的用户> ~/.rmc-gateway` 改回来即可，服务端下一次读取
就会自动恢复，不必重启（它读不到账号表时会往日志里写一条指向属主/权限的
`ERROR`，那条日志就是这件事的现场证据）。

这道属主检查是靠「在数据目录里建一个临时文件」做的，所以**连 `account list` 这种只读命令也要求数据目录属主相符、且可写**。想在别的账号下只看一眼账号表，今天没有只读的路子——用 `sudo -u <serve 用的用户> rmc-gateway account list`。

### `account passwd` 不会踢掉已经连着的那条隧道

**这是既定行为，不是缺陷。** `passwd` 只换掉 `accounts.toml` 里的口令哈希；
服务端那条吊销扫描只看账号是不是还 `enabled`，不看口令有没有变过。所以：

- **改了口令，已经连着的那条隧道会继续活到它自己断为止**（现场关掉客户端、
  网络断开、`serve` 重启……），新口令只对**下一次认证**生效；
- **要立刻把人断掉，用 `account revoke`**——它最迟 10 秒内踢掉在线会话。
  吊销之后那个账号名不能再复用，要恢复服务就用 `account add` 开一个新账号、
  发一条新的连接码。

换句话说，`passwd` 回答的是"以后谁能连进来"，`revoke` 回答的是"现在谁在里面"。
口令泄露这类场景要的是后者，先 `revoke`，再按需要开新账号。

## 客户网络只放行 443 时

`--listen`（进程真正监听的地址）与 `config.toml` 里的 `public_addr`
（写进连接码、客户端真正拨的地址）是两个独立的值。两条出路，都不需要 root 进程：

- 请客户网管放行这台机器的 22000；
- 或者在服务器防火墙 / 云厂商端口映射上把公网 **443 转到本机 22000**，
  把 `config.toml` 的 `public_addr` 改成 `<IP>:443`，再 `account list` 重取连接码发下去。

**不要重跑 `init`** —— 身份密钥已存在时它拒绝覆盖，改地址只需要改 `config.toml`。

## 审计日志

`~/.rmc-gateway/audit/audit-YYYY-MM-DD.log`，JSON Lines，一天一个文件，保留 180 天。

记的是：服务启动、认证成功与失败、来源封禁、隧道建立与拆除、
工程师连接的起止（来源、端口、时长、双向字节数）、被拒的工程师连接、账号的增删改。
**不写口令**；失败的认证只记账号名与来源。
来源 IP 是**真实地址**，不是 127.0.0.1。

## 工程师登录一体机

```
ssh -p <该账号的端口> root@<运维服务器的 IP>
```

在运维服务器上不需要账号，它也不参与这一段认证；密码是那台一体机的动态 root 口令。
**每次都要核对一体机的 host key 指纹**：不同的一体机会先后复用同一个端口，
`known_hosts` 的变更告警在这里是常态，不能一律回车放过。让现场人员打开「诊断」页，
念出「一体机 host key 指纹」那一行的 `SHA256:…`，与你这边 ssh 提示的指纹比对。

## 常见故障

| 现象 | 原因与处理 |
|---|---|
| 现场连不上 22000 | 防火墙没放行 22000–22999；或客户出网只放 443，见上面那一节 |
| 现场报「账号或口令不正确」 | 口令错，或**账号已被吊销**——两种情况的应答故意不可区分（不泄露账号是否存在）。用 `account list` 确认启用状态，必要时 `account passwd` 重置 |
| 现场报指纹不符 | 路径上有 TLS 审计设备，或连接码过期（本机换过身份密钥）。用 `fingerprint` 与连接码里的指纹比对 |
| 端口被占 | 旧隧道还没判死（心跳 10 秒 × 3）。客户端会自己重试，最长 120 秒 |
| 吊销了但人还在线 | 最迟 10 秒；超过这个时间用 `status` 看那条隧道还在不在，不在就是已经踢掉了 |
| `status` 说没在跑 | 进程真的没起（`systemctl status rmc-gateway`），或 `status.json` 已过期。它**按状态文件的更新时间**判断（超过 30 秒没更新就判为没在跑），不会打印一份过期的在线列表；**pid 只是打印出来供 `systemctl`/`ps` 交叉核对，不参与判活**——所以 `kill -9` 之后的头 30 秒里 `status` 仍会报「运行中（pid N）」，而那个 pid 已经不指向任何进程 |
| `serve` 拒绝启动 | 以 root 跑了（换普通用户，容器里才用 `--allow-root`）；或数据目录属主不是当前用户——CLI 与 `serve` 要同一个用户 |

## 已知限制

- **单实例**：没有多实例高可用，也没有防止两个 `serve` 共用同一个数据目录的锁。
- **反向端口默认公网可达**（原方案已明确接受的取舍）。
  `serve --engineer-allow <CIDR>`（可重复给）能把它收窄到公司出口网段。
  **装成开机自启时这些参数必须在 `service print` 那一次原样带上**（见部署第 5 步）
  ——前台试跑用过的参数不会被继承，漏带就是静默地对全互联网开放。
- **吊销过的账号名不能复用**：`account add` 会拒绝同名，端口也一并保留，换一个名字。
- 发布物只有 x86_64 Linux；没有 Web 管理界面、没有口令自助修改、没有第二因素。
