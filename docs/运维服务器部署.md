# 运维服务器（rmc-gateway）

一个二进制。不装软件包，不要域名，不要证书，不需要 root。

## 部署（一台干净的 x86_64 Linux）

1. 建一个普通用户（或用现有的），把 GitHub Actions `core` 工作流的
   `rmc-gateway-linux-x86_64` 产物拷到它的 PATH 里（musl 静态链接，不挑发行版）；
2. `rmc-gateway init --public-addr <这台机器的公网 IP>:22000`
   —— 这个地址会写进每一条连接码，客户端照它拨号；
3. 防火墙放行 TCP **22000–22999**（22000 给现场客户端，22001–22999 给远程工程师）；
4. `rmc-gateway serve` 先在前台跑通一次；开机自启用 `rmc-gateway service print`
   生成的 systemd 单元，安装命令就印在它输出开头那几行注释里（本程序自己不装、不改系统）；
5. 记下 `rmc-gateway fingerprint` 的输出并**备份 `~/.rmc-gateway/`**
   —— 身份密钥丢了，所有连接码作废，得重新发一遍。

## 开通账号 / 重置口令 / 吊销 / 看谁在线

```
rmc-gateway account add <账号>     # 开通，端口自动取区间里最小的空闲号（--port 可指定）
rmc-gateway account passwd <账号>  # 重置口令，新口令只显示这一次
rmc-gateway account revoke <账号>  # 吊销，最迟 10 秒内踢掉在线会话
rmc-gateway account list           # 所有账号、端口、启用状态与各自的连接码
rmc-gateway status                 # 本机是否在跑、有哪些在线隧道
```

`account add` 打印四行：账号与端口、**连接码**、**初始口令（只显示这一次）**、
给远程工程师的 ssh 命令。连接码里没有秘密，可以走普通渠道发；**口令单独发**。
连接码随时能用 `account list` 重取，口令重取不了，只能 `account passwd` 重置。

## 客户网络只放行 443 时

`--listen`（进程真正监听的地址）与 `config.toml` 里的 `public_addr`
（写进连接码、客户端真正拨的地址）是两个独立的值。两条出路，都不需要 root 进程：

- 请客户网管放行这台机器的 22000；
- 或者在服务器防火墙 / 云厂商端口映射上把公网 **443 转到本机 22000**，
  把 `config.toml` 的 `public_addr` 改成 `<IP>:443`，再 `account list` 重取连接码发下去。

**不要重跑 `init`** —— 身份密钥已存在时它拒绝覆盖，改地址只需要改 `config.toml`。

## 审计日志

`~/.rmc-gateway/audit/audit-YYYY-MM-DD.log`，JSON Lines，一天一个文件，保留 180 天。

记的是：服务启动、认证成功与失败、来源封禁、隧道建立与拆除、
工程师连接的起止（来源、端口、时长、双向字节数）、被拒的工程师连接、账号的增删改。
**不写口令**；失败的认证只记账号名与来源。
来源 IP 是**真实地址**，不是 127.0.0.1。

## 工程师登录一体机

```
ssh -p <该账号的端口> root@<运维服务器的 IP>
```

在运维服务器上不需要账号，它也不参与这一段认证；密码是那台一体机的动态 root 口令。
**每次都要核对一体机的 host key 指纹**：不同的一体机会先后复用同一个端口，
`known_hosts` 的变更告警在这里是常态，不能一律回车放过。让现场人员打开「诊断」页，
念出「一体机 host key 指纹」那一行的 `SHA256:…`，与你这边 ssh 提示的指纹比对。

## 常见故障

| 现象 | 原因与处理 |
|---|---|
| 现场连不上 22000 | 防火墙没放行 22000–22999；或客户出网只放 443，见上面那一节 |
| 现场报「账号或口令不正确」 | 口令错，或**账号已被吊销**——两种情况的应答故意不可区分（不泄露账号是否存在）。用 `account list` 确认启用状态，必要时 `account passwd` 重置 |
| 现场报指纹不符 | 路径上有 TLS 审计设备，或连接码过期（本机换过身份密钥）。用 `fingerprint` 与连接码里的指纹比对 |
| 端口被占 | 旧隧道还没判死（心跳 10 秒 × 3）。客户端会自己重试，最长 120 秒 |
| 吊销了但人还在线 | 最迟 10 秒；超过这个时间用 `status` 看那条隧道还在不在，不在就是已经踢掉了 |
| `status` 说没在跑 | 进程真的没起（`systemctl status rmc-gateway`），或 `status.json` 已过期——它按 pid 与更新时间判断，不会打印一份过期的在线列表 |
| `serve` 拒绝启动 | 以 root 跑了（换普通用户，容器里才用 `--allow-root`）；或数据目录属主不是当前用户——CLI 与 `serve` 要同一个用户 |

## 已知限制

- **单实例**：没有多实例高可用，也没有防止两个 `serve` 共用同一个数据目录的锁。
- **反向端口默认公网可达**（原方案已明确接受的取舍）。
  `serve --engineer-allow <CIDR>`（可重复给）能把它收窄到公司出口网段。
- **吊销过的账号名不能复用**：`account add` 会拒绝同名，端口也一并保留，换一个名字。
- 发布物只有 x86_64 Linux；没有 Web 管理界面、没有口令自助修改、没有第二因素。
