# 远程运维客户端 使用手册

现场人员在笔记本上点一下「开启远程维护」，公司的远程工程师就能登录到客户内网里的
一体机；点「停止远程维护」，通道立即关闭。**通道只能由现场人员从里面打开。**

```
一体机 ──现场网段── 现场笔记本（本客户端） ══ TLS 443 ══▶ 运维服务器 ◀── ssh ── 远程工程师
```

| 你是 | 看哪几节 |
|---|---|
| 现场人员（操作笔记本的人） | §1 – §6，出了问题看 §9 |
| 远程工程师 | §7 |
| 运维（管运维服务器与账号的人） | §8 |

> 本手册对应 0.1.0。它按代码与方案写成；**Windows 真机验收
> （`docs/windows-验收清单.md`）还没走完**，§11 列了当前版本已知的限制。

---

## 1. 开始之前

- 一台 Windows 笔记本，接在**一体机所在的网段**，同时能上网（直连或经代理都行）。
- `rmc.exe`：单个文件，不用安装，**不需要管理员权限**，双击就运行。
- 向运维要三样：**运维服务器地址**、**账号**（`tunnel-` 开头）、**初始密码**。
- 一体机的地址与 SSH 端口（界面默认填的是 `192.168.1.1` 与 `61001`）。

## 2. 开启远程维护

1. 双击 `rmc.exe`。窗口标题是「远程运维客户端」，通知区出现一个灰色圆点。
2. 在「维护」页的 **维护目标** 里填一体机的地址和端口。
3. 在 **运维服务器** 里填地址和端口（默认 443）、账号、密码。
   「出网」一行是**自动检测**的，显示「直连」或「经系统代理 …」，不用填；
   公司或客户的代理要求域认证时，也**不需要输入任何代理的用户名密码**。
4. 点 **开启远程维护**。按钮点不了，说明有框没填对，框下面的红字会说是哪一个。
5. 状态卡依次走过「预检中 → 正在连接 → 已连接」。**变绿之后，告诉远程工程师可以连了。**

连上之后账号密码区会收起、地址锁定，状态卡显示已连接的时长。
**没有时长上限**——不点停止，它就一直开着。

## 3. 状态一览

维护页顶部的状态卡与通知区的圆点，颜色始终一致。

| 状态卡 | 颜色 | 意思 | 你要做什么 |
|---|---|---|---|
| 未开启 | 灰 | 远程维护默认关闭 | — |
| 预检中 / 正在连接 | 蓝 | 正在检查网络、登录、注册端口 | 等着；想放弃点「取消」 |
| 已连接 | 绿 | 隧道已建立，远程工程师可以接入一体机 | — |
| 一体机不可达 | 橙 | 通道是好的，但笔记本连不上一体机。会自动重试，恢复后自动变回绿色 | 看一体机开机没有、网线、笔记本还在不在那个网段 |
| 正在重连 · 第 n 次 | 琥珀 | 笔记本的网络断了，正在自动重连；**密码已保留，不用重输** | 等着，或点「立即重试」 |
| 正在停止 | 灰 | 正在关闭隧道与全部远程会话 | 等着 |
| 连接失败 | 红 | 这类失败**不会自动重试**，卡片上写着原因 | 按原因处理后点「重试」 |

**密码填错**不走红色：界面回到「未开启」，密码框被清空，其余内容保留，重输即可。

## 4. 远程会话与通知

- 已连接后，「远程会话」一栏列出当前接进来的每一个会话和它的双向流量；
  没有人接入时显示「暂无远程会话」。
- 每条会话右边有 **断开**：只断这一条，隧道和别的会话不受影响。
- 系统通知只在你需要知道的时候弹：有会话接入或结束、一体机不可达或已恢复、
  连接失败。**网络抖动引起的重连不弹**。
- 鼠标悬停在通知区圆点上能看到当前状态。点它没有反应（当前版本没有菜单）。

## 5. 停止与退出

- 点 **停止远程维护**：全部远程会话立即断开，运维服务器上的端口立即释放。
- **关闭窗口就是退出程序，远程维护随之停止。** 要保持维护，把窗口最小化，不要关。
- 同一时间只能运行一个客户端，再双击一次不会开出第二个窗口。

## 6. 记住密码

- 默认**不保存**。勾上「记住密码」并连接成功后，密码会加密存在本机，
  下次打开时账号、运维服务器地址和密码都已填好。
- 密文绑定**当前这个 Windows 账号**。换一个 Windows 账号登录、或者把文件拷到
  别的机器上，都解不开——界面会提示重新输入，这是正常的。
- 取消勾选，存着的密码**当场删除**。

---

## 7. 远程工程师：怎么连

```
ssh -p <该账号的端口> root@<运维服务器地址>
```

- 你在运维服务器上不需要账号。密码是那台一体机的动态 root 口令，
  从公司口令服务按设备编号取。
- 连不上，先问现场人员状态卡是不是**绿色**；橙色说明隧道通了但一体机不可达。
- **每次都要核对一体机的 host key 指纹。** 不同的一体机会先后复用同一个端口，
  所以 `known_hosts` 的变更告警在这里是常态，不能一律回车放过。让现场人员打开
  「诊断」页，念出「一体机 host key 指纹」那一行的 `SHA256:…`，与你这边 ssh
  提示的指纹比对。

## 8. 运维

部署、开通与吊销账号、服务器侧的故障表，都在 `gateway/README.md`。与客户端有关的三件事：

- **当前版本的客户端固定申请反向端口 22000**，界面上没有填端口的地方；而运维服务器
  是按账号限定端口的。所以**现阶段只有登记为 22000 的那一个账号连得上**，登记成
  别的端口的账号会在「正在连接」这一步失败。见 `docs/交付前还剩什么.md` 第 5 条。
- **首次连接要核对运维服务器的 host key。** 客户端第一次连上时会把指纹记在本机，
  诊断页「运维服务器 host key」一行显示「（首次记录）」。请把它与服务器上
  `ssh-keygen -lf /etc/ssh/tunnel_host_ed25519_key.pub` 的输出核对一次。
  此后指纹不一致，客户端会**直接拒绝连接**，并且不重试。
- 运维服务器确实换过主机密钥：先核对新指纹，再删掉现场笔记本上的
  `%LOCALAPPDATA%\rmc\known_hosts`。

## 9. 出了问题

**第一步看「诊断」页。** 它列出最近一次开启时的检查结果：一体机 TCP、一体机
host key 指纹、运维服务器域名解析、运维服务器 TLS，以及系统代理、代理 CONNECT、
代理认证、运维服务器 host key。哪一项没过，下面会给一段处置建议。

**第二步导出诊断包。** 点「导出诊断包」，文件写到
`%LOCALAPPDATA%\rmc\rmc-diagnostics-<时间>.zip`（界面不提示位置，要自己去这个目录找），
把它交给远程工程师。包里是环境信息、检查结果和日志；**密码不会进包**。

**「日志」页**可以按 全部 / 信息 / 警告 / 错误 筛选，也可以搜索；
「打开日志目录」直接打开存放日志的文件夹。日志一天一个文件，保留 30 天。

| 现象 | 原因与处理 |
|---|---|
| 「开启远程维护」点不了 | 有框没填或填错，看框下面的红字 |
| 点了之后回到「未开启」，密码框被清空 | 密码不对，或账号被锁。重输；还不行找运维 |
| 橙色「一体机不可达」 | 一体机没开机、它的 sshd 没起来，或者笔记本不在一体机那个网段 |
| 一直「正在重连」 | 笔记本断网了。网络一恢复它会立即重连，不用等倒计时走完 |
| 合上盖子休眠过 | 唤醒后几秒内自动恢复，不用操作 |
| 诊断页说服务器证书不受信任 | 客户网络上有 TLS 审计设备。请客户的网络管理员把运维服务器的 443 端口加进放行名单 |
| 诊断页说代理要求认证、协商没通过 | 看「代理认证」那一行写的原因；多半要网络管理员给当前 Windows 用户开出网权限 |
| 红色，提示 host key 不一致 | **不要自己处理。** 联系运维核对指纹（§8）——也可能是连接被引到了冒充的服务器上 |
| 提示端口被占用 | 上一次是异常断开的，服务器要 80–90 秒才回收端口。客户端会自动重试 |

## 10. 文件都在哪

全部在 `%LOCALAPPDATA%\rmc\` 下，卸载就是删掉这个目录和 `rmc.exe`。

| 路径 | 内容 |
|---|---|
| `logs\rmc-YYYY-MM-DD.log` | 日志，保留 30 天 |
| `known_hosts` | 记下来的运维服务器指纹 |
| `secrets\*.sealed` | 「记住密码」的密文，只有保存它的那个 Windows 账号解得开 |
| `last-account.txt` | 上次用的账号、运维服务器地址与端口——**没有密码** |
| `rmc-diagnostics-*.zip` | 导出的诊断包 |

## 11. 当前版本的已知限制

- 反向端口固定为 22000（§8）。
- 不勾「记住密码」时，地址和账号每次打开都要重填。
- 「复制检查结果」按钮还没有功能。
- 导出诊断包之后，界面不提示它存到了哪儿（§9）。
- 通知区圆点不能点击；Windows 资源管理器重启之后圆点会消失，**程序其实还在运行**。
- 只有浅色界面。

完整清单见 `docs/交付前还剩什么.md`。
